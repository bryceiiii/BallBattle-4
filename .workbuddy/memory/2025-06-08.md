# 2025-06-08 多人联机优化

## 第一轮：移动卡顿 + 分裂性能 + 碰撞抖动
1. **移动卡顿** — 服务端20Hz推送 + SmoothDamp(0.08s)过快，产生"走-停-走"效果
2. **分裂卡顿** — N个球触发N倍回调 + 服务端O(n²)聚拢逻辑在circleA循环内
3. **碰撞抖动** — 分裂后碰撞体立即启用 → 物理推开 ↔ SyncBallPos ↔ 服务端修正 振荡循环

### 第一轮修改
- `CircleController.cs` — 死推算(Dead Reckoning) + 沉降期(Settling 0.8s) + 兄弟球IgnoreCollision
- `GameManager.cs` — PlayerBallMap追踪 + Physics2D.IgnoreCollision注册 + 每帧更新去重
- `PlayerInputController.cs` — 公开CurrentDirection属性
- `server-csharp/spacetimedb/Lib.cs` — playerBalls字典移到循环外 + 聚拢逻辑独立执行

## 第二轮：视觉瞬移 + 穿墙抖动
4. **视觉瞬移** — 死推算在方向变化时，extrapolatedVelocity突变 → 推算位置跳跃 → 球视觉瞬移
5. **穿墙抖动** — 服务端无边界钳制 → 球移出世界 → SyncBallPos上报 → 位置被物理推开 → 再次向界外移动 → 振荡

### 第二轮修改
- `CircleController.cs` — **移除死推算**，改为直接SmoothDamp到服务端位置；remote平滑时间0.12s；新增ClampToWorldBounds()；新增CheckWallProximity()在边界2单位内抑制SyncBallPos
- `server-csharp/spacetimedb/Lib.cs` — 新增ClampEntityToBounds()，在MoveAllPlayer移动后、聚拢移动后、SyncBallPos写入前均钳制位置到[radius, WORLD_SIZE-radius]

## 第三轮：移除SyncBallPos + 软分离替代物理碰撞

用户反馈：仍有小卡顿 + 不同玩家球碰撞贴合时抖动

根因：前两轮只解决了同玩家球的碰撞（Physics2D.IgnoreCollision），不同玩家球的物理碰撞仍然存在：
  物理即时反弹 → 下帧SmoothDamp拉回 → 振荡抖动

### 第三轮修改
- `CircleController.cs` — **彻底清理**：
  - 删除 syncCheckTimer / SYNC_INTERVAL / POS_OFFSET_THRESHOLD（SyncBallPos触发逻辑）
  - 删除 CheckWallProximity() / isNearWall（边界同步抑制）
  - 删除 IgnoreCollisionWith() 方法
  - **所有球碰撞体默认禁用**（col.enabled = false，Start中）
  - 新增 public bool IsInAnimation 属性供分离系统跳过动画中的球
  - 保留 ClampToWorldBounds() 作为安全钳制

- `GameManager.cs` — **核心重构**：
  - 删除 SetupSiblingCollisionIgnore() 及相关 IgnoreCollisionWith 调用（碰撞体已全局禁用）
  - 新增 ResolveAllCircleOverlaps() 软分离系统（LateUpdate中执行）
    - 只分离不同玩家球
    - 跳过动画中的球（分裂/合并/沉降）
    - 每帧只分离重叠量的15% → 配合SmoothDamp产生无抖动贴边滑动
  - 保留 PlayerBallMap 用于清理追踪

### 软分离原理
```
Unity物理碰撞：重叠→瞬间弹开⚡→下帧SmoothDamp拉回→再弹开→抖动
软分离系统： 重叠→每次推15%🐌→SmoothDamp同时趋近服务端位置→平滑共存
```

## 最终架构
| 组件 | 职责 |
|------|------|
| 服务端 MoveAllPlayer | 权威移动+边界钳制+吞噬检测+聚拢 |
| 客户端 SmoothDamp | 向服务端位置平滑收敛(remote 0.12s/local 0.05s) |
| 客户端 软分离 | 不同玩家球渐进推开(15%/帧) |

| ❌ SyncBallPos | 已移除，不再回传客户端位置 |
| ❌ Unity物理碰撞 | 已禁用，ball collider enabled = false |

## 第四轮：SyncBallPos 彻底删除 + Rigidbody2D 物理碰撞（球球大作战风格）

用户要求：
1. SyncBallPos 从客户端和服务器端彻底删除
2. 不要简单禁用碰撞体，参照球球大作战逻辑修复不同玩家球碰撞抖动

### 第四轮修改

- `CircleController.cs` — **Rigidbody2D + 速度驱动**：
  - 新增 `[RequireComponent(typeof(Rigidbody2D))]`
  - 启用碰撞体（恢复 col.enabled = true）
  - Start() 中配置 Rigidbody2D：drag=1.5, Continuous CD, Interpolate
  - **用速度驱动替代 SmoothDamp**：`rb.velocity = (targetPos - rb.position) / smoothTime`
    - 关键优势：物理引擎在 FixedUpdate 中自然处理碰撞反弹，不再与 SmoothDamp 的拉回冲突
    - drag=1.5 确保碰撞后反弹快速衰减 → "贴边滑动"而非抖动
  - 动画期间 `rb.isKinematic = true`，运动学模式手动控制位置
  - 沉降/正常期间 `rb.isKinematic = false`，动态模式物理处理碰撞

- `GameManager.cs` — **恢复同玩家碰撞忽略**：
  - 恢复 SetupSiblingCollisionIgnore()（碰撞体重新启用）
  - 删除 ResolveAllCircleOverlaps() 软分离（物理引擎接管）
  - 保留 PlayerBallMap、去重等优化

- `server-csharp/spacetimedb/Lib.cs` — **删除 SyncBallPos Reducer**：
  - 完全移除 SyncBallPos reducer 及其注释
  - 保留 ClampEntityToBounds()（移动和聚拢中仍使用）

### 速度驱动 vs SmoothDamp 原理对比
```
SmoothDamp: Update() → transform.position = ...  ← 绕过物理引擎
    碰撞 → 物理反弹 → 下帧 SmoothDamp 直接拉回 → 振荡

速度驱动:   Update() → 计算 desiredVelocity
            FixedUpdate() → rb.velocity = desiredVelocity  ← 物理引擎处理
    碰撞 → 物理反弹修改速度 → 下帧速度趋近 target → 平滑共存
```

### 最终架构
| 组件 | 职责 |
|------|------|
| 服务端 MoveAllPlayer | 权威移动+边界钳制+吞噬检测+聚拢 |
| 服务端 ClampEntityToBounds | 位置绝不越界 |
| 客户端 Rigidbody2D | 动态物理碰撞（不同玩家球自然推挤） |
| 客户端 速度驱动 | rb.velocity = delta/smoothTime 趋近服务端位置 |
| 客户端 Physics2D.IgnoreCollision | 同玩家球忽略碰撞 |
| ❌ SyncBallPos | 已删除（客户端+服务端） |
| ❌ SmoothDamp/transform | 已替换为 Rigidbody2D 速度驱动 |
