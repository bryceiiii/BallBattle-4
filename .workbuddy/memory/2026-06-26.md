### 网络性能优化（Quick Tunnel 延迟卡顿）
**诊断**：全量审查服务端 Lib.cs + 客户端 11 个脚本 + Quick Tunnel 配置，识别 5 个关键瓶颈。
**实施**：
1. **客户端预测** (CircleController.cs) — Dead Reckoning 死推算：本地玩家即时响应输入（0ms），服务端位置仅用于温和修正（自适应 blendFactor），输入→画面延迟从 ~180ms 降至 ~50ms
2. **Tick Rate 降低** (Lib.cs) — 50Hz→25Hz，减少 ~50% 网络流量和 ~40% 服务端 CPU
3. **SmoothDamp WAN调优** (CircleController.cs) — remotePosSmoothTime 0.10→0.15s，scaleSmoothTime 0.06→0.08s
4. **自动重连** (SpacetimeDBNetworkManager.cs) — 断线检测 + 自动重连（3s间隔，最多10次）
5. **RTT测量+调试显示** — PlayerInputController 发送时间戳 + CircleController 回算 RTT + NetworkDebugDisplay.cs (F3切换)
6. **QUIC协议** (start-tunnel.ps1) — cloudflared 从默认 http2(TCP) 切换为 quic(UDP)，避免 TCP 队头阻塞

### Bug修复 — 预测抖动 + 卡顿 + LAN连接失败 (19:50)
**根因分析**：
- **抖动**: `SERVER_DELTA_PREDICT = 0.040f` 被用于每帧 FixedUpdate（实际步长 0.02s），导致预测速度 = 服务端的 2 倍，叠加 `Lerp(blendFactor=0.4)` 暴力修正 → 来回剧烈抖动
- **卡顿**: `Lerp` 无机惯性记忆，每帧"硬切"目标位置导致可见跳跃
- **LAN不通**: `ActiveUri = $"https://{host}:{port}"` → 本地 SpacetimeDB 无 TLS 证书，TLS 握手直接失败

**修复**：
1. 移除硬编码 `SERVER_DELTA_PREDICT`，改用 `Time.fixedDeltaTime`（~0.02s），预测步长与 FixedUpdate 频率一致
2. 修正算法从 `Lerp` 改为 `SmoothDamp`（独立 `_predictVelocity`），保留速度记忆，修正平滑连续
3. LAN URI 从 `https://` 改为 `http://`
4. `Connect()` 方法新增重置 `_wasConnected/_isReconnecting/_reconnectAttempts`，确保新连接状态干净

**新建文件**: NetworkDebugDisplay.cs
