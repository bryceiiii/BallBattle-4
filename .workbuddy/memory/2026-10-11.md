## 解除"手机端请使用局域网模式"限制（本机模拟移动端调试）
- 现象：在电脑上想本机调试移动端，点"本机服务器"被告知"手机端请使用局域网模式"、连接被拦。
- 根因：`SpacetimeDBNetworkManager.Connect()` 开头有 `#if UNITY_ANDROID || UNITY_IOS` 条件块，在移动平台构建下直接拦截 `ConnectionMode.Local`（真机 127.0.0.1 指向手机自己，确实连不上）。
- 修复：条件改为 `#if (UNITY_ANDROID || UNITY_IOS) && !UNITY_EDITOR` —— 编辑器里模拟移动端放行 Local，仅真机（非编辑器）保留提示。
- 注意：编辑器里 `IsMobileMode` 由场景 `PlatformInputManager.forceMobileInEditor`（MainScene.unity:2919，当前 0）决定；若要 PC 上完整模拟移动端输入，需把它勾成 1。

## 修复：连接失败后仍能通过 SkinSelectionPanel 连接/进入
- 现象：连接失败（或连接断开）后，`SkinSelectionPanel` 依然可用，玩家能绕过大厅限制继续操作/进入游戏。
- 根因（两处叠加）：
  1. `SkinSelectionUIController` 只监听 `OnConnected` → `Show()`，**没有监听失败/断线来隐藏面板**，失败后面板残留显示。
  2. `SpacetimeDBNetworkManager` 有"3 秒超时兜底把 `IsConnected` 强制置 true"的逻辑，而 `HandleConnectError` 未置 `_fallbackTriggered`；失败后 Db!=null、_connectStartTime>0，3 秒后兜底把失败**误判为成功** → `LobbyUIController` 轮询检测到 false→true → 再次 `Show()` 皮肤面板（假连接）。
- 修复：
  - `SpacetimeDBNetworkManager.HandleConnectError`：失败时 `_fallbackTriggered = true`，禁止兜底把失败改判为成功。
  - `SkinSelectionUIController`：新增 `OnConnectFailed` 回调（隐藏面板 + 回大厅）并注册/注销；`OnConfirmClicked` 加防御检查（`net.IsConnected` 为假则隐藏面板回大厅，不进游戏）；新增 `Update()` 兜底——面板显示期间检测到 `!IsConnected` 自动关闭。`Show()` 唯一调用点在 `LobbyUIController:287`（连接成功后），不会误关。
- 客户端改动，无需 publish。

## 修复：死亡面板按钮点击无效 / 无法返回皮肤选择界面
- 现象：死亡后 Respawn 按钮、新增的"换皮肤"按钮都点不动。
- 排查（读 YAML 定位，非猜）：
  - `DeathPanel.prefab`（guid a8361330169095544a3d486176d586a8）里 **RespawnBtn 的 `m_OnClick.m_Calls: []` 是空的**，且**没有换皮肤按钮**。
  - 场景 `MainScene.unity` 里有一个该 prefab 的实例（PrefabInstance fileID 1123558149），挂在 **HudCanvas 的直接子物体** `3762903346586483382` 下（`m_TransformParent: 1539998624`），`m_IsActive: 0`，位置 (960,-432)。这就是"已做成预制体"的那块。
  - `HudCanvas.prefab` 里 HudController 的序列化字段 `deathPanel/deathTitleText/respawnButton` **全是 `{fileID: 0}`（空）** → 运行时 `deathPanel==null` → 走 `BuildDeathPanel()` 又生成了一套 **重复面板**；用户点到的是没绑事件的那套 → 点不动。
  - HudCanvas 有 GraphicRaycaster（guid dc42784cf147c0c48a680349fa168899），Canvas 是 Overlay、ReceivesEvents=1，**射线层没问题**，问题纯在引用/绑定。
- 修复（`HudController.cs`）：
  1. 新增字段 `public GameObject deathPanelPrefab;`（拖 DeathPanel.prefab）。
  2. `Start()` 死亡面板解析优先级：Inspector 引用 → **`FindExistingDeathPanel()`（在自身子节点找名为 DeathPanel、或含 RespawnBtn 子节点的面板）** → 实例化 deathPanelPrefab → 代码生成。解决重复面板 + Prefab 引用场景实例的死结。
  3. 新增 `ResolveDeathPanelRefs()`：从面板里自动解析 Title/RespawnBtn，并**运行时补建"换皮肤"按钮**（位置跟随 RespawnBtn 正下方，避免重叠）。
  4. 新增 `public void BindDeathPanelButtons()`：在 `Start()` 里**无条件**补绑两个按钮的 onClick（`RemoveListener` 后 `AddListener`，防重复）。这是"预制体路径不绑事件"的正解 —— Prefab 无法引用场景里的 HudController，只能运行时绑。
  5. 三个回调加 Debug.Log（点不到时可看 Console 是"没日志"还是"有日志但逻辑失败"）。
  6. `ShowDeathScreen()` 加 `SetAsLastSibling()` 置顶 + 状态日志。
  7. `HudCanvas.prefab` 里补 `deathPanelPrefab: {fileID: 6967286201474029147, guid: a8361330169095544a3d486176d586a8}` 与 `backToSkinButton: {fileID: 0}` 字段。
- 关键经验：**Unity UI 按钮点不动，先查三件事** —— ① `m_PersistentCalls.m_Calls` 是否为空（Inspector 没连事件）；② Canvas 是否有 GraphicRaycaster；③ 是否有全屏 raycastTarget 遮罩/重复面板盖住。Prefab 无法序列化对场景对象的引用 → **必须运行时 AddListener**。
