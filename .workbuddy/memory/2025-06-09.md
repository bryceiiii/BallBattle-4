## 修复合并功能失效

### 问题诊断
合并功能完全失效，三个根因：
1. `MergePlayerCheck` 要求玩家完全静止(dir≈0)才触发合并 — 玩家移动时永远不合并
2. 标记 `isMerging=true` 后同一 tick 内就删除球 — 客户端动画还没播完球就没了
3. 合并后清零所有存活球的 `touchStartMs` — 导致下一轮必须重新等待

### 修复方案
- **服务端 `MergePlayerCheck`**：
  - 去掉静止限制，玩家边移动也可以合并
  - 每次定时器只合并一对（`return` 退出），真正逐对合并
  - 标记 `isMerging=true` 后**不删除球**，等客户端通知
  - `isMerging` 的球跳过移动/吞噬/聚拢逻辑
  - 质量转移提前到大球（动画期间大球已变重）
- **新增服务端 `FinishMerge` Reducer**：客户端动画完成后调用，真正删除小球
  - 安全检查：只有球所属玩家才能触发删除
- **客户端 `CircleController`**：
  - 合并动画时间从 1.5s 缩短为 0.8s
  - 动画播完后调用 `InvokeFinishMerge(entityId)` 通知服务端
  - 新增 `MergeTimeoutRecovery` 协程：1.5s 后若服务端未删除则恢复物理状态
- **客户端 `GameManager`**：
  - `OnCircleUpdated` 中找合并目标改为 `FindBiggestBallOfPlayer(playerId)` 而非只找本地玩家最大球
  - 新增 `FindBiggestBallOfPlayer` 方法
- **autogen**：
  - 手动创建 `FinishMerge.g.cs` 和注册分发

### 涉及文件
- `server-csharp/spacetimedb/Lib.cs` - MergePlayerCheck 重写 + FinishMerge 新增 + MoveAllPlayer/吞噬/聚拢跳过 isMerging
- `Client-unity/Assets/Scripts/CircleController.cs` - 合并动画流程改造
- `Client-unity/Assets/Scripts/GameManager.cs` - 合并目标查找改用同玩家最大球
- `Client-unity/Assets/autogen/Reducers/FinishMerge.g.cs` - 新建

### Bug 修复：HP 条显示在摄像机外 + 位置偏上 + Canvas 未激活
- **根因**：World Space Canvas 的 sizeDelta 用了像素值（120×10），但游戏世界是 50×50 单位，球直径仅 ~1.12。HP 条相当于 120 单位宽 → 跨越整个地图
- **修复**：sizeDelta 改为世界单位（初始 1.0×0.12，动态跟随球大小缩放）
- **修复 2**：锚点嵌套运算错误 → 改用 Canvas 自身的 localPosition 每帧控制位置
- **修复 3**：SetHp 原代码只控制了 BG（子对象）显隐，未激活 Canvas → 改为控制 hpBarBgGo.SetActive()
- **修复 4**：偏移量从 `diameter*0.5 + 0.35` 减为 `diameter*0.5 + 0.15`，更贴近球体
- 额外：绑定 worldCamera = Camera.main，Z 偏移 -0.01 确保在球前方渲染

### 调试功能：H 键扣血 + HP 条位置可调
- **服务端**：新增 `DebugDamage` reducer（调试用，按 H 键扣 10 HP）
- **客户端**：`GameManager.Update` 监听 H 键 → 调用 DebugDamage 对自己最大球扣血
- **CircleController**：新增 7 个 public 可序列化字段，可在 Unity Inspector 中直接调 HP 条位置：
  - `hpBarYOffsetMultiplier`（半径倍数，默认 0.5）
  - `hpBarYOffsetFixed`（固定间距，默认 0.15）
  - `hpBarWidthRatio`（宽度比例，默认 0.8）
  - `hpBarMinWidth`（最小宽度，默认 0.4）
  - `hpBarHeight`（高度，默认 0.12）
  - `hpBarZDepth`（Z 轴深度，默认 -0.01）
  - `hpBarInitialYOffset`（创建初始偏移，默认 0.7）
