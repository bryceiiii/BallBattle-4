# 2026-06-18 — 手机端连接与数据订阅问题

## 最终根因
SpacetimeDB SDK 在 Android IL2CPP 上**从后台线程触发 `HandleConnect` 回调**。
这导致 `OnConnected` 事件分发到 `GameManager.SubscribeToTables()` 时也在后台线程执行——
事件订阅 (`Conn.Db.Food.OnInsert += ...`) 在后台线程上虽然语法执行了，但实际**不会触发**，
IL2CPP 静默吞掉 GameObject 操作（Instantiate / transform.position）。

PC 上一切正常，因为 HandleConnect 始终在 Unity 主线程触发。

## 修复方案（已实施）
- **`GameManager.SubscribeToTables()` 增加主线程检测**：
  - 通过 `_lastUpdateFrame == Time.frameCount` 判断当前是否在主线程
  - 后台线程调用：标记 `isSubscribed=true`（避免重复进入），直接 return
  - 主线程调用：正常注册事件 + 调用 `SubscribeToAllTables()`
- **`GameManager.Update()` 主线程兜底**：
  - 每帧设置 `_lastUpdateFrame = Time.frameCount`（主线程标记）
  - 发现 `!_mainThreadSubscribed && IsConnected` → 重置 `isSubscribed=false` → 重新调用 SubscribeToTables
- **`SpacetimeDBNetworkManager.HandleConnect()`**：
  - 不再调用 `SubscribeToAllTables()`（由 GameManager 在主线程上唯一负责）
  - 只发 OnConnected 事件
- **`SpacetimeDBNetworkManager.Update()` 3秒兜底**：
  - HandleConnect 完全不触发时强制设置 `IsConnected=true`，由 GameManager 兜底订阅

## 关键设计原则
- 单一来源：所有 SpacetimeDB 订阅操作只能在 Unity 主线程执行
- 兜底轮询：每帧检测状态，不依赖后台线程事件
- 标志位分离：`isSubscribed`（是否已处理） vs `_mainThreadSubscribed`（是否在主线程上完成）

## 关键参数
- `Time.frameCount` 每帧 +1，配合 `_lastUpdateFrame` 静态字段做主线程检测
- `IsConnected` 标志位被 `LobbyUIController.Update` 轮询，UI 不依赖事件
