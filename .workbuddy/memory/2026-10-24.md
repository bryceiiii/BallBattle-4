## 修复射击摇杆位置偏移（unityMCP）
- 现象：手机端右侧射击摇杆位置严重偏移，实际完全在屏幕外。
- 诊断（通过 unityMCP `execute_code` 读 RectTransform 精确值 + `GetWorldCorners` 换算屏幕坐标）：
  - `MobileTouchCanvas/ShootJoystickBg`：锚点 (0.88, 0.15)，但 `anchoredPosition = (729.6, -382.4)`。
  - 点锚点（anchorMin == anchorMax）下 anchoredPosition 是**相对锚点再叠加**，实际 x ≈ 0.88×1920+729.6 = 2419（画布仅宽 1920）→ 完全出屏。
  - 屏幕角点实测 x 3878→4186，左摇杆对照组 547→1013，确认。
- 根因：git HEAD 里该值是 `(0, 0)`，工作区被误拖成 (729.6, -382.4)。
- 修复：`rt.anchoredPosition = Vector2.zero`，Undo.RecordObject + SetDirty + SaveScene。
  修后屏幕角点 2662→2970 / 53→379（画布空间 83%→93% x、3.7%→26% y），回到画布内。
- 排除项：`MobileCanvasSetup.buildOnStart=false`（不会重复构建画布）；场景内仅 1 个 MobileTouchCanvas；
  `MobileInputController.aimJoystick` 正确引用 ShootJoystickBg；运行时不改写该坐标。
- Console Error 0 条。
- 未改任何脚本，仅改场景中该 RectTransform 一个字段。

## 修复分裂按钮与射击摇杆重叠 + 排行榜过大（unityMCP）
- 诊断方法：用 `RectTransform.GetWorldCorners` + 父级 Canvas 的 `InverseTransformPoint` 换算**归一化坐标**（0~1），
  比 `WorldToScreenPoint` 可靠（后者在编辑器 Game View 缩放下会给出超屏的错值）。
- **分裂按钮 vs 射乔摇杆**：
  - `ShootJoystickBg` NORM x[0.832, 0.928] y[0.037, 0.263]
  - `SplitButton` NORM x[0.751, 0.855] y[0.014, 0.245] → 横向重叠 2.3% 屏宽

- **排行榜过大的三层根因**：
  1. `HudCanvas/Leaderboard` 节点 `localScale = 1.47`（lossyScale 达 2.45，而 HUD 画布本身只有 1.67）→ 归 1。
  2. 代码硬编码下限 `Mathf.Max(40f, rowHeight)` + `Mathf.Clamp(panelWidth, 286f, 306f)`，
     而场景里用户早已设成 `22 / 200` → 被强行抬回 `40 / 286`，**用户怎么调 Inspector 都没用**。
     已改为 `Clamp(rowHeight, 24, 56)` / `Clamp(panelWidth, 200, 360)`，并在场景里显式写入 `24 / 200`。
  3. **嵌套 Canvas 的 RectTransform 陷阱**：`BuildUI()` 原来在 `Leaderboard`（100×100）下新建 `LeaderboardCanvas`
     （ScreenSpaceOverlay 但 `isRootCanvas=false`），嵌套 Canvas 的 rect 继承父级 100×100，
     导致 Panel 的 (1,1) 锚点算错，world pos 跑到 (3165, 1451)，顶边溢出画布（NORM y 到 1.033）。
     改为 Panel 直接 `SetParent(GetComponentInParent<Canvas>().transform)` + `SetAsLastSibling()`，
     与其它 HUD 共用同一套 CanvasScaler。
- 内部元素同步缩小：header 34→26、title 14→10、badge 28→20、skin 24→18、name 13→11、mass 12→10、
  settings 70×26→56×22、fold 26→22；name/hpBg 左偏移 72→50。

## unityMCP 原生工具为什么没挂载（根因已定位）

结论：`~/.workbuddy/mcp.json` 写得对，但**缺信任记录**，被 `McpTrustStore` 判定为 `trust-pending` 直接过滤掉。

证据链（解包 `E:\WorkBuddy\resources\app.asar` → `/main/server.js`）：
- sidecar 启动参数带 `--mcp-config=<8838字节> --strict-mcp-config`，**只认 app 生成的配置**，
  用户级 mcp.json 必须经 McpManager 的 `UserMcpProvider` 汇总进去才会出现。
- `UserMcpProvider.build()`：`enabled: !c.disabled`、`trusted: this.trust.isApproved(id, hash)`。
- `isBlocked(e){ return !e.enabled || !e.trusted }`，未信任 ⇒ `blockedReason:'trust-pending'` 被丢弃。
- `approvalKey(id,hash) = \`${hash}::${publicName}\``；http 传输的 `trustMaterial` 只用 **origin**
  （`http://127.0.0.1:8080`），hash = sha256(origin)。
- daemon 日志 `resolveMcpServers resolved {projectMcpCount:0, runtimeMcpCount:6}` → 6 个都是内置/一方，
  unityMCP 从未进入（`mcp-tool-list.json` 里也没有它的工具缓存）。

已做的修复：
- 写 `~/.workbuddy/mcp-approvals.json`：
  `d30a576c...070e::unityMCP`（另附 3 种键序变体兜底），值为毫秒时间戳。
- `~/.workbuddy/mcp.json` 保持 `type:streamableHttp` / `url:http://127.0.0.1:8080/mcp` / `disabled:false`。

注意：
- `McpTrustStore.load()` 只在 `bootstrap()` 执行一次，**没有 fs.watch**；
  `mcp.json` 同理只在启动/`mcp:refresh` 时重读 ⇒ 改完必须重启 WorkBuddy（含托盘）才生效。
- 进程树：21052 Electron main → 12648 `daemon-app-server-entry.js` → 29796 `sidecar-entry.js` → 21940 `codebuddy --serve`。
  **别 kill 12648**，会连带杀掉当前会话的 agent 进程。
- 服务端已用 HTTP 握手实测：`mcp-for-unity-server 3.4.9`，`tools/list` 49 个工具
  （manage_scene/manage_editor/read_console/execute_code/manage_gameobject…）。
